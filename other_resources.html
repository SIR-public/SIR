Other Resources

The SIR project in is always seeking additional resources useful for software testing and engineering studies. If you are aware of a repository that is not listed here please email the SIR administrator.

SIR invariant subjects were prepared for use in conjunction with the Sireum software analysis platform. Sireum uses a number of static analysis techniques to facilitate program analysis using user defined properties. This platform is maintained and supported by the Computing and Information Sciences Department of Kansas State University.

NASA provides Java Pathfinder, JPF, a framework specifically tailored for concurrency testing. This framework is utilized by several SIR (concurrency) subjects.

The SPL2go website provides a catalog of software product line testing subjects suitable for testing studies. This site is maintained by the METOP GmbH (Mensch Technik Organisation Planung) Institute in affiliation with the Otto von Guericke University of Magdeburg.

The Defects4J project is a collection of reproducible bugs found in real-world Java open source applications. The associated conference paper, "Defects4J: A Database of Existing Faults to Enable Controlled Testing Studies for Java Programs" by René Just, Darioush Jalali, and Michael Ernst, can be found at https://people.cs.umass.edu/~rjust/publ/defects4j_issta_2014.pdf

Similar to Defects4J, the iBugs site provides a benchmark testing database that compliments the SIR with subjects real world bugs. The research supporting this is contained in the paper Extraction of Bug Localization Benchmnarks from History by Valentin Dallmeier and Thomas Zimmermann at Saarland University and the University of Calgary.

The National Institute of Standards and Technology (NIST) provides the SAMATE Reference Dataset containing a set of known security flaws. The dataset provides test cases and targeted test suites, code samples with flawed and fixed code and demonstrative inputs that expose the faults. The types of faults presented in these artifacts include those found "in the wild" (real faults) along with seeded faults. The SAMATE Reference Dataset is available at http://samate.nist.gov/SRD

The Common Weakness Enumeration community web ( http://cwe.mitre.org/ provides definitions and discussions on software weaknesses and security considerations. While this site is focused on security concerns, software testing and security tools and techniques are discussed extensively.

The PROMISE (http://openscience.us/repo) project has compiled a sizable array of software engineering experiment data. Further description on this repository can be found in the paper: T. Menzies, R. Krishna, and D. Pryor, The Promise Repository of Empirical Software Engineering Data, North Carolina State University, Department of Computer Science, 2015.

The FOSSology tookkit https://github.com/fossology/fossology offers a framework for software analysis tools permitting the identification of software licenses, as well as extract MIME type and meta data from their collection of open source projects.

The Cooperari tool site hosts tools for cooperative testing of multithreaded Java programs including support for the Eclipse IDE.

Boa is a web-based API to perform statistical analysis on software repositories. These analyses provide data and meta-data examinations of the myriad of software projects to be found on the web. Utilizing a custom query language, searches can be initiated on the content and properties of these software projects providing insight into questions of language use, project management, source code content, and software engineering metrics.

The Software Assurance Marketplace, SWAMP provides open source packages that manifest one or more weaknesses or vulnerabilities that can be exploited or studied in experimentation. Along with these vulnerable subjects, they also provide references to tools useful in revealing the weaknesses present in the subjects.
